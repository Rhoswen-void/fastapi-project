-> POSTMAN is an application that allows us to work with APIs and test without having to open the browser or create a 
   frontend specifically to test APIs.

-> To add some data to the body of the request we use body in the POSTMAN application

-> Why we need a Schema? (Schema is the format that tells us what the data should look like)
   * It's a pain to get all the values from the body
   * The client can send whatever data they want
   * The data isn't getting validated
   * We want to force the client to send data in a schema that we expect

-> CRUD Operations (4 main units of an application)
Create -> POST -> @app.post("/posts")

Read -> GET -> @app.get("/posts/{id}")
            -> @app.get("/posts")

Update -> PUT/PATCH -> @app.put("/posts/{id}) (when we use put all of the fields need to used when use patch only the specific field(s) that require a change need to be entered)

Delete -> DELETE -> @app.delete("/posts/{id}")

Command to run a uvicorn server:
1. When the file using fastAPI is not in any folder we generally use
   > uvicorn <python_file_name>:<name_of_instance_of_fastAPI>
   > uvicorn <python_file_name>:<name_of_instance_of_fastAPI> --reload

   Now the difference with using reload and without using reload is that when any change is made to the code
   while using reload the server detects a change and automatically restarts the server with the new
   changes.

2. When the file using fastAPI is inside a designated folder then we use
   > uvicorn <folder_name>.<python_file_name>:<name_of_instance_of_fastAPI>
   > uvicorn <folder_name>.<python_file_name>:<name_of_instance_of_fastAPI> --reload
